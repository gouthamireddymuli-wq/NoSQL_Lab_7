1. Single-Document Atomicity vs Multi-Document Transactions

In MongoDB, writes to a single document are atomic by design. However, when coordinating operations across multiple collections—such as freezing a Threat Actor's state in threat_actors while simultaneously setting 50 related observables to quarantined in indicators—a multi-document transaction is essential to prevent partial updates.

Snapshot Isolation Guarantees:

  • Read Concern: snapshot guarantees that reads within the transaction observe a point-in-time consistent snapshot of the data.
  • Write Concern: majority ensures the commit is durably replicated across the majority of replica set nodes before acknowledging.

Concurrency & Write Conflicts:

  • If two concurrent transactions attempt to modify the same document, a TransientTransactionError or write-conflict exception is raised.
  • MongoDB drivers provide automated retry mechanisms for transient errors.

2. PyMongo ACID Transaction Implementation 

with client.start_session() as session:
    with session.start_transaction(
        read_concern=ReadConcern("snapshot"),
        write_concern=WriteConcern("majority")
    ):
        # 1. Update Threat Actor Status
        db.threat_actors.update_one(
            {"actor_id": "actor-001"},
            {"$set": {"status": "SANCTIONED_SEIZED", "updated_at": datetime.utcnow()}},
            session=session
        )
        
        # 2. Atomically Quarantine All Related Threat Indicators
        db.indicators.update_many(
            {"attribution.threat_actors.actor_id": "actor-001"},
            {"$set": {"status": "quarantined", "confidence": 100}},
            session=session
        )
        
        # Commit transaction durably across replica set nodes
        session.commit_transaction()
