1. Production Topology & Kubernetes StatefulSet Patterns

Unlike stateless microservices, deploying a distributed database like MongoDB requires stateful identity, stable network hostnames, and persistent storage attached to each peer.

Kubernetes StatefulSet Architecture:

  • Stable Network IDs: Pods receive persistent ordinals (mongo-0, mongo-1, mongo-2) resolving via headless Kubernetes service DNS.
  • Persistent Volume Claim Templates: Each pod automatically binds to dedicated cloud block storage (EBS gp3 or GCE PD).

Docker Compose Multi-Node Replica:

  • Deploys 3 separate containers on an isolated bridge network with healthcheck commands.
  • Initialization service executes rs.initiate() once all containers are healthy.

2. Kubernetes StatefulSet Specification 

apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mongo-cti-cluster
spec:
  serviceName: "mongo-headless"
  replicas: 3
  selector:
    matchLabels:
      app: mongo
  template:
    metadata:
      labels:
        app: mongo
    spec:
      containers:
      - name: mongodb
        image: mongo:8.0
        command: ["mongod", "--replSet", "rs0", "--bind_ip_all"]
        ports:
        - containerPort: 27017
        volumeMounts:
        - name: mongo-data
          mountPath: /data/db
  volumeClaimTemplates:
  - metadata:
      name: mongo-data
    spec:
      accessModes: [ "ReadWriteOnce" ]
      resources:
        requests:
          storage: 100Gi
