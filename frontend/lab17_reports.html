1. Vector Search Architecture in MongoDB Atlas

Traditional keyword full-text search ($text) fails when threat actors use polymorphic aliases, encrypted jargon, or oblique references. Vector search embeds unstructured threat advisories into 768-dimensional geometric space where semantic similarity equals cosine proximity.

HNSW (Hierarchical Navigable Small World):

  • Constructs a multi-layer geometric graph of vectors. Top layers enable fast long-distance hops.
  • Trade-off: Sub-5ms query latency at >98% recall, with slightly higher RAM usage during index builds.

IVF (Inverted File Index):

  • Partitions vector space into Voronoi cells using k-means clustering. Searches only centroids closest to query.
  • Trade-off: Lower RAM footprint, but query recall drops if k-means centroids aren't periodically retrained.

2. MongoDB $vectorSearch Pipeline in PyMongo 

def rag_semantic_search(query_text, k=3):
    # 1. Embed query using embedding model
    query_vector = embed_text(query_text)
    
    # 2. Vector search aggregation pipeline in MongoDB
    pipeline = [
        {
            "$vectorSearch": {
                "index": "threat_reports_vector_index",
                "path": "embedding",
                "queryVector": query_vector,
                "numCandidates": 100,
                "limit": k
            }
        },
        {
            "$project": {
                "report_id": 1,
                "title": 1,
                "summary": 1,
                "score": { "$meta": "vectorSearchScore" }
            }
        }
    ]
    return list(db.reports.aggregate(pipeline))
